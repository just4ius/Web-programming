# ADR 0002: Шарова архітектура модульного моноліту (Layered Architecture)

## Статус
Прийнято (Accepted)

## Дата
2026-10-18

## Контекст
Для запобігання спагеті-коду та неконтрольованого зчеплення компонентів у моноліті необхідно чітко зафіксувати відповідальність кожного шару, правила напрямку залежностей та список заборонених зв'язків.

У проєкті реалізується багатошарова структура для кожного виділеного доменного контексту (зокрема `Document & Page Management`).

## Рішення
Встановлюється 4-шарова структура проєкту:

```
[ Клієнт / HTTP запит ]
          │
          ▼
┌────────────────────────────────────────┐
│  1. API Layer (api/)                   │  <-- Контролери, маршрути, HTTP DTO, валідація запиту
└──────────────────┬─────────────────────┘
                   │
                   ▼
┌────────────────────────────────────────┐
│  2. Service Layer (service/)           │  <-- Use-Cases, бізнес-правила, оркестрація, мапінг DTO <-> Domain
└─────────┬────────────────────┬─────────┘
          │                    │
          ▼                    ▼
┌───────────────────┐  ┌─────────────────┐
│ 3. Domain Layer   │  │ 4. Repository   │  <-- Чисті сутності й агрегати (domain/)
│    (domain/)      │  │    (repository/)│  <-- Доступ до даних / PostgreSQL / пам'ять
└───────────────────┘  └─────────────────┘
```

### 1. Шар API (`api/`)
- **Призначення:** Обробка зовнішніх HTTP-запитів, маршалінг та демаршалінг JSON у DTO.
- **Вміст:** Express-роутери, контролери ендпоінтів (`pageRouter.js`), middleware валідації та обробки помилок.
- **Відповідальність:**
  - Отримання HTTP-запиту (headers, body, params, query).
  - Базова синтаксична валідація структури DTO.
  - Виклик відповідного методу сервісу.
  - Формування HTTP-відповіді відповідно до API-контракту (статус-коди 200, 201, 204, 400, 404, 500).

### 2. Шар сервісів (`service/`)
- **Призначення:** Реалізація конкретних користувацьких сценаріїв (Use Cases) та прикладної бізнес-логіки.
- **Вміст:** Прикладні сервіси (наприклад, `PageService.js`).
- **Відповідальність:**
  - Бізнес-валідація вхідних даних (перевірка інваріантів, дозволів, існування сутностей).
  - Оркестрація операцій між доменними сутностями та сховищем (репозиторієм).
  - Мапінг між зовнішніми DTO та внутрішніми сутностями домену (`Domain Entity <-> DTO`).
  - Генерація доменних помилок (`ValidationError`, `NotFoundError`).

### 3. Шар домену (`domain/`)
- **Призначення:** Інкапсуляція сутностей предметної області, коренів агрегатів та їхніх інваріантів.
- **Вміст:** Доменні моделі (`Page.js`, `Block.js`, `User.js`).
- **Відповідальність:**
  - Збереження власного стану сутності.
  - Методи зміни стану (`rename`, `archive`, `restore`, `addBlock`, `removeBlock`).
  - Гарантування внутрішніх інваріантів (непорожність обов'язкових полів, валідність переходів станів).
  - Повна ізольованість від зовнішнього світу: доменний шар нічого не знає про HTTP, Express, SQL, ORM чи JSON.

### 4. Шар доступу до даних (`repository/`)
- **Призначення:** Абстракція зберігання та вибірки даних для доменних моделей.
- **Вміст:** Репозиторії (наприклад, `PageRepository.js`), клієнт пулу з'єднань БД (`db.js`).
- **Відповідальність:**
  - Виконання SQL-запитів до таблиць `pages`, `blocks`, `users`.
  - Мапінг рядків бази даних у доменні об'єкти `Page`.

## Напрямок залежностей
Залежності дозволені **виключно зверху вниз**:
- `api/` залежить від `service/`
- `service/` залежить від `domain/` та `repository/`
- `domain/` **не залежить ні від кого** (чисте ядро)

## Заборонені зв’язки (Anti-patterns):
1. **`api/` -> `repository/` або `db.js` (ЗАБОРОНЕНО):** Контролери ніколи не звертаються безпосередньо до бази даних чи SQL-запитів.
2. **`api/` -> бізнес-логіка (ЗАБОРОНЕНО):** Жодних бізнес-перевірок, маніпуляцій з полями чи розрахунків у контролерах.
3. **`domain/` -> `api/`, `service/`, `db.js` (ЗАБОРОНЕНО):** Доменні класи ніколи не імпортують Express, HTTP-хедери чи SQL-драйвери.
4. **Крос-контекстні прямі виклики репозиторіїв:** Якщо іншому сервісу потрібні дані сторінки, він звертається через `PageService`, а не напряму до таблиці `pages`.
