# Глосарій термінів та концепцій системи

Глосарій фіксує єдину термінологію (Ubiquitous Language) для бізнес-аналітиків, інженерів розробки, тестувальників та дизайнерів платформи.

---

## 1. Базові сутності домену

| Термін (UK) | Термін (EN) | Опис, призначення та бізнес-правила |
| :--- | :--- | :--- |
| **Робочий простір** | **Workspace** | Головний ізольований контейнер для компанії, проєкту або команди. Містить окрему підписку (білінг), пул користувачів, дерево документів та параметри безпеки. Дані між різними просторами суворо ізольовані. |
| **Користувач** | **User** | Глобальний обліковий запис фізичної особи в системі. Зберігає облікові дані для входу (email, пароль, налаштування 2FA), профіль (ім'я, аватар) та список усіх робочих просторів, де користувач має доступ. |
| **Учасник простору** | **Workspace Member** | Проміжна сутність зв'язку «багато-до-багатьох» між `User` та `Workspace`. Визначає роль і права користувача в межах конкретного робочого простору. |
| **Роль доступу** | **Role (RBAC)** | Набір дозволів у просторі: <br>• **Owner** — повний контроль, білінг та видалення простору; <br>• **Admin** — налаштування простору, керування учасниками та інтеграціями; <br>• **Editor** — створення й редагування будь-якого контенту; <br>• **Viewer** — доступ лише для перегляду та коментування/експорту. |
| **Сторінка** | **Page** | Базовий документ бази знань. Виступає як стаття (складається з набору блоків) або як папка (може містити дочірні підсторінки). Має метадані: назву, emoji-іконку, обкладинку та дату оновлення. |
| **Батьківська сторінка** | **Parent Page** | Документ вищого рівня, в який вкладено поточну сторінку. Кореневі сторінки верхнього рівня мають `parent_id = null`. Переміщення батьківської сторінки переносить усе дочірнє дерево. |
| **Дерево навігації** | **Page Tree / Hierarchy** | Ієрархічна структура документів без циклів (Directed Acyclic Graph). Організовує знання за принципом довільної вкладеності: `Workspace → Проєкт → Спринт → Завдання`. |
| **Блок** | **Block** | Атомарна одиниця контенту всередині сторінки. Кожен абзац, заголовок, зображення чи чекбокс — окремий блок зі своїм UUID, типом, стилями та позицією у вертикальному масиві. |
| **Тип блоку** | **Block Type** | Схема візуалізації та поведінки блоку: текст (`paragraph`), заголовки (`h1`, `h2`, `h3`), списки (`bullet_list`, `todo_item`), код з підсвіткою (`code`), цитата (`quote`), плашка (`callout`), медіа-вставка тощо. |
| **База даних / Таблиця** | **Database / Data Table** | Колекція структурованих записів із чітко типізованими колонками (властивостями). Підтримує сортування, фільтрацію, реляційні зв'язки та різні режими відображення (таблиця, дошка, список, календар). |
| **Властивість таблиці** | **Property / Column** | Стовпець схеми таблиці даних. Має фіксований тип (`Text`, `Number`, `Single/Multi-Select`, `Date`, `Checkbox`, `Person`, `Relation`, `Formula`), який валідує всі значення в цьому полі. |
| **Запис бази даних** | **Row / Record / Entry** | Одиничний рядок таблиці даних. Може функціонувати як самостійна `Page`, що має власне тіло з блоками контенту. |
| **Вкладення** | **Attachment** | Файл будь-якого формату (зображення, PDF, архів), завантажений у сховище файлів (наприклад, S3) і прив'язаний через URL та метадані до сторінки чи блоку. |
| **М'яке видалення (Кошик)** | **Soft Delete / Trash** | Стан тимчасового видалення (`is_archived = true`). Документ приховується з робочого простору та навігації зі збереженням можливості відновлення або остаточного видалення (Hard Delete). |

## 2. Полісемія: розмежування термінів за контекстами (Bounded Contexts)

У межах системи деякі терміни набувають різного технічного значення залежно від конкретного піддомену:

### 1. `User` (Користувач)
* **Identity & Access Management (IAM):** Суб'єкт безпеки з обліковими даними (email, хеш пароля, сесії, токени).
* **Document Management:** Метадані авторства сторінки — `created_by` (первинний автор) або `last_edited_by` (редактор ревізії).
* **Structured Data:** Значення поля типу `Person` (наприклад, виконавець задачі `Assignee` або рев'юер).

### 2. `Page` (Сторінка)
* **Document Management:** Вузол навігаційної ієрархії (`parent_id`, індекс сортування, права доступу, слаг у URL).
* **Block Editor:** Полотно (Canvas), яке містить упорядкований масив ідентифікаторів блоків (`ordered list of block IDs`).

### 3. `Table` (Таблиця)
* **Block Editor (Simple Table):** Проста презентаційна сітка клітинок для візуального форматування нетипізованого тексту.
* **Structured Data (Inline Database):** Повноцінна реляційна структура з типізованою схемою колонок, фільтрацією та валідацією.

### 4. `Property` (Властивість)
* **Block Editor:** Параметри відображення окремого блоку (колір тексту, стан чекбокса, мова коду тощо).
* **Structured Data:** Опис стовпця бази даних (тип даних, список допустимих значень селекта, формули).
