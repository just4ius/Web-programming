# Глосарій термінів (Ubiquitous Language)

Цей документ визначає єдину мову (Ubiquitous Language) предметної області платформи ведення бази знань, регламентів та заміток (Notion Clone). Усі терміни мають однакове значення для бізнес-аналітиків, розробників бекенду, фронтенду та бази даних.

---

## 1. Ключові терміни домену

| Термін (UK) | Термін (EN) | Однозначне визначення |
| :--- | :--- | :--- |
| **Робочий простір** | **Workspace** | Ізольоване середовище організації, проєкту чи команди, що об'єднує користувачів, дерево документів, таблиці та системні налаштування. |
| **Користувач** | **User** | Зареєстрований акаунт фізичної особи в системі, що містить автентифікаційні дані (email, пароль) та глобальний профіль. |
| **Учасник простору** | **Workspace Member** | Сутність, що зв'язує конкретного користувача з робочим простором та визначає його рівень доступу й права в ньому. |
| **Роль** | **Role** | Рівень прав учасника у робочому просторі згідно з моделлю RBAC: `Owner` (Власник), `Admin` (Адміністратор), `Editor` (Редактор), `Viewer` (Читач). |
| **Сторінка** | **Page** | Базовий інформаційний вузол бази знань. Має назву, іконку, обкладинку, позицію в ієрархії та складається з блоків контенту або дочірніх сторінок. |
| **Батьківська сторінка** | **Parent Page** | Документ вищого рівня, до якого логічно прикріплена поточна сторінка, формуючи ієрархічне дерево знань. Кореневі сторінки не мають батьківської сторінки (`parent_id = null`). |
| **Ієрархічне дерево** | **Page Hierarchy / Tree** | Структура орієнтованого графа без циклів, що організовує сторінки робочого простору у вкладені розділи та підрозділи. |
| **Блок** | **Block** | Атомарна, незалежна одиниця контенту всередині сторінки (абзац, заголовок, пункт списку, фрагмент коду тощо), яка має свій порядок і параметри відображення. |
| **Тип блоку** | **Block Type** | Класифікатор функціонального призначення та структури блоку (наприклад: `paragraph`, `heading_1`, `heading_2`, `heading_3`, `todo_item`, `bullet_list`, `code`, `quote`, `callout`). |
| **Вбудована таблиця** | **Data Table / Inline Database** | Структурований об'єкт бази знань всередині сторінки або простору, що має фіксовану типізовану схему стовпців та набір рядків. |
| **Стовпець таблиці** | **Column / Property** | Елемент схеми таблиці даних, що має власну назву, тип (`text`, `number`, `select`, `date`, `checkbox`) та необов'язкові параметри (наприклад, перелік опцій для вибору). |
| **Рядок таблиці** | **Table Row / Record** | Одиничний запис у таблиці даних, що містить значення для визначених стовпців відповідно до їхніх типів. |
| **Вкладення** | **Attachment** | Бінарний файл (зображення, PDF, архів), завантажений користувачем та прикріплений до сторінки або медіа-блоку. |
| **Архівація (Кошик)** | **Archive / Trash** | Стан м'якого видалення сторінки чи таблиці (`is_archived = true`), що приховує об'єкт з навігаційного дерева зі збереженням можливості відновлення або остаточного видалення. |

## 2. Розмежування термінів між піддоменами (Disambiguation)

Окремі поняття мають специфічні значення залежно від обмеженого контексту (Bounded Context):

### 1. `User` (Користувач)
* **В контексті IAM (Identity & Access):** `User` — це суб'єкт автентифікації з обліковими даними (email, password hash, токени безпеки, статус активації).
* **В контексті Document Management:** це `Author` (автор, який створив сторінку) або `LastEditor` (ідентифікатор користувача, який востаннє редагував документ).
* **В контексті Structured Data:** це `Assignee` або значення типу поля `Person`, де користувач виступає суто посиланням на особу, відповідальну за конкретний запис у таблиці.

### 2. `Page` (Сторінка)
* **В контексті Document Management:** `Page` — це вузол дерева навігації (ієрархія `parent_id`, порядок відображення в меню, права доступу, архівація).
* **В контексті Block Editor:** `Page` — це полотно/контейнер для послідовного масиву блоків (`ordered list of Blocks`).

### 3. `Table` (Таблиця)
* **В контексті Block Editor:** проста презентаційна таблиця для форматування тексту (статична матриця комірок без типізації).
* **В контексті Structured Data (Inline Database):** повноцінна типізована реляційна база даних з динамічною схемою колонок, фільтрацією та валідацією записів.

### 4. `Property` (Властивість)
* **В контексті Block Editor:** атрибути форматування блоку (наприклад, колір фону, стан `checked` для todo, мова програмування для блоку коду).
* **В контексті Structured Data:** опис колонки таблиці (тип даних, обмеження, заголовок).
