# Моделювання домену: Піддомени, Сутності та Інваріанти

Цей документ описує предметну область платформи ведення бази знань та регламентів (Notion Clone) за принципами Domain-Driven Design (DDD).

---

## 1. Структура піддоменів (Subdomain Decomposition)

Проєкт розділений на 5 піддоменів за їхнім бізнес-значенням та характером складності:

```
                            ┌────────────────────────────────────────┐
                            │               NOTION CLONE             │
                            └────────────────────────────────────────┘
                                                │
         ┌───────────────────────────────┬──────┴────────────────────────┬───────────────────────────────┐
         ▼                               ▼                               ▼                               ▼
┌───────────────────┐           ┌───────────────────┐           ┌───────────────────┐           ┌───────────────────┐
│    Core Domain    │           │Supporting Domain 1│           │Supporting Domain 2│           │  Generic Domains  │
├───────────────────┤           ├───────────────────┤           ├───────────────────┤           ├───────────────────┤
│  Document & Page  │           │   Block Engine    │           │  Structured Data  │           │ • Identity & Access│
│    Management     │           │  (Content Editor) │           │ (Inline Databases)│           │ • Assets & Storage│
└───────────────────┘           └───────────────────┘           └───────────────────┘           └───────────────────┘
```

### 1.1. Core Domain (Основний домен)
* **Document & Page Management (Управління документами та сторінками):**
  * *Обґрунтування:* Основна конкурентна перевага та цінність Notion-подібного застосунку полягає в гнучкій деревоподібній структурі сторінок (сторінки можуть бути вкладеними на будь-яку глибину), зручній навігації, метаданих сторінок та життєвому циклі документів (створення, переміщення, архівація, відновлення).

### 1.2. Supporting Subdomains (Допоміжні піддомени)
* **Block Engine / Content Editor (Блоковий редактор вмісту):**
  * *Обґрунтування:* Контент сторінки моделюється не як монолітний текст (HTML чи Markdown), а як набір поліморфних блоків (абзаци, заголовки, списки, to-do, код тощо). Кожен блок має свій тип, порядок та специфічні властивості.
* **Structured Data / Inline Databases (Вбудовані таблиці даних):**
  * *Обґрунтування:* Можливість створювати структуровані бази даних/таблиці всередині сторінок із динамічною схемою колонок (текст, число, вибір зі списку, дата, прапорець) та рядками даних для ведення внутрішнього обліку (обладнання, сервери, задачі).

### 1.3. Generic Subdomains (Загальні піддомени)
* **Identity & Access Management (IAM / Автентифікація та доступ):**
  * *Обґрунтування:* Стандартний функціонал реєстрації, входу користувачів, створення робочих просторів (Workspaces) та управління ролями за моделлю RBAC (`Owner`, `Admin`, `Editor`, `Viewer`).
* **Assets & Media Storage (Файли та медіа-вкладення):**
  * *Обґрунтування:* Зберігання завантажених зображень, обкладинок сторінок та файлів-додатків, валідація розмірів та типів MIME.

## 2. Сутності, Атрибути та Інваріанти за Контекстами

---

### Контекст 1: Identity & Access Management (IAM)

#### 1. `User` (Сутність / Entity)
Обліковий запис користувача системи.
* **Атрибути:**
  * `id` (`UUID` або `Int`) — унікальний ідентифікатор користувача.
  * `email` (`String`, обов'язкове, унікальне) — адреса електронної пошти.
  * `passwordHash` (`String`, обов'язкове) — захешований пароль (bcrypt/argon2).
  * `displayName` (`String`, обов'язкове) — ім'я користувача для відображення в інтерфейсі (довжина 2–100 символів).
  * `avatarUrl` (`String`, опціональне) — URL-посилання на аватар.
  * `createdAt` (`DateTime`) — дата та час створення акаунту.
* **Інваріанти:**
  * `email` повинен відповідати валідному формату електронної пошти та бути унікальним.
  * `passwordHash` не може зберігатися у відкритому вигляді.
  * `displayName` не може бути порожнім рядком.
* **Доменні методи:**
  * `changeDisplayName(newName)` — оновлення імені з валідацією.
  * `updatePassword(newHash)` — оновлення пароля.

#### 2. `Workspace` (Корінь агрегату / Aggregate Root)
Командний або особистий робочий простір, що ізолює всі ресурси.
* **Атрибути:**
  * `id` (`UUID` або `Int`) — унікальний ідентифікатор простору.
  * `name` (`String`, обов'язкове) — назва робочого простору (3–100 символів).
  * `slug` (`String`, обов'язкове, унікальне) — URL-ідентифікатор (наприклад, `my-team`).
  * `ownerId` (`UUID` або `Int`, обов'язкове) — ідентифікатор користувача-власника.
  * `members` (`List<WorkspaceMember>`) — колекція учасників простору.
  * `createdAt` (`DateTime`) — час створення.
* **Інваріанти:**
  * Простір обов'язково повинен мати хоча б одного власника (`Owner`).
  * `ownerId` завжди має бути серед учасників зі статусом `Owner`.
  * `slug` повинен містити лише латинські символи, цифри та дефіси.
* **Доменні методи:**
  * `addMember(user, role)` — додати користувача до простору із зазначеною роллю.
  * `removeMember(userId)` — видалити користувача (заборонено видаляти останнього власника).
  * `changeMemberRole(userId, newRole)` — змінити роль учасника.
  * `transferOwnership(newOwnerId)` — передати права власника іншому учаснику.

#### 3. `WorkspaceMember` (Сутність / Entity)
Зв'язок користувача з простором та його повноваження.
* **Атрибути:**
  * `userId` (`UUID` або `Int`, обов'язкове) — посилання на користувача.
  * `workspaceId` (`UUID` або `Int`, обов'язкове) — посилання на простір.
  * `role` (`Role Enum`: `Owner`, `Admin`, `Editor`, `Viewer`) — роль учасника.
  * `joinedAt` (`DateTime`) — дата приєднання до простору.
* **Інваріанти:**
  * Користувач може мати лише один активний запис членства в межах одного простору.
* **Доменні методи:**
  * `canEdit()` — повертає `true`, якщо роль `Owner`, `Admin` або `Editor`.
  * `canManageMembers()` — повертає `true`, якщо роль `Owner` або `Admin`.

### Контекст 2: Document & Page Management (Core Domain)

#### 1. `Page` (Корінь агрегату / Aggregate Root)
Одинична сторінка / документ у базі знань.
* **Атрибути:**
  * `id` (`UUID` або `Int`) — унікальний ідентифікатор сторінки.
  * `workspaceId` (`UUID` або `Int`, обов'язкове) — робочий простір, якому належить сторінка.
  * `parentId` (`UUID` або `Int`, опціональне, `null` для кореневих сторінок) — посилання на батьківську сторінку.
  * `title` (`String`, за замовчуванням `"Untitled"`) — назва сторінки.
  * `icon` (`String`, опціональне) — емодзі або іконка сторінки (наприклад, 📄).
  * `coverUrl` (`String`, опціональне) — посилання на банер-обкладинку сторінки.
  * `isArchived` (`Boolean`, за замовчуванням `false`) — ознака перебування в кошику.
  * `position` (`Float` або `Int`, за замовчуванням `0`) — порядковий номер для сортування в сайдбарі.
  * `createdBy` (`UUID` або `Int`, обов'язкове) — автор створення.
  * `blocks` (`List<Block>`) — упорядкований список блоків контенту.
  * `createdAt` (`DateTime`) — час створення.
  * `updatedAt` (`DateTime`) — час останньої модифікації.
* **Інваріанти:**
  * `Page` не може бути батьком для самої себе (`parentId !== id`).
  * Деревоподібна структура не може містити циклічних залежностей (A -> B -> A).
  * Батьківська сторінка `parentId` повинна належати до того самого `workspaceId`.
  * При архівації сторінки (`archive()`) всі її дочірні сторінки вважаються прихованими.
* **Доменні методи:**
  * `rename(newTitle)` — зміна заголовка сторінки та оновлення `updatedAt`.
  * `setIcon(icon)` — встановлення іконки.
  * `setCover(url)` — оновлення обкладинки.
  * `moveTo(newParentId, newPosition)` — переміщення сторінки на інший рівень ієрархії із захистом від циклів.
  * `archive()` — помістити сторінку в кошик.
  * `restore()` — відновити сторінку з кошика.
  * `addBlock(block, targetIndex)` — додати блок контенту на конкретну позицію.
  * `removeBlock(blockId)` — видалити блок зі сторінки.
  * `reorderBlocks(orderedBlockIds)` — перевпорядкування блоків на сторінці.

### Контекст 3: Block Engine / Content Editor

#### 1. `Block` (Сутність / Entity)
Атомарна одиниця контенту на сторінці.
* **Атрибути:**
  * `id` (`UUID` або `Int`) — унікальний ідентифікатор блоку.
  * `pageId` (`UUID` або `Int`, обов'язкове) — сторінка, якій належить блок.
  * `type` (`BlockType`, обов'язкове) — тип блоку (`paragraph`, `heading_1`, `heading_2`, `heading_3`, `todo_item`, `bullet_list`, `numbered_list`, `code`, `quote`, `callout`, `divider`).
  * `content` (`String`, за замовчуванням `""`) — текстовий вміст блоку.
  * `properties` (`Object / JSON`, опціональне) — специфічні властивості:
    * для `todo_item`: `{ checked: Boolean }`
    * для `code`: `{ language: String }`
    * для `callout`: `{ icon: String, color: String }`
  * `parentBlockId` (`UUID` або `Int`, опціональне) — батьківський блок для багаторівневих списків.
  * `position` (`Int`, обов'язкове) — порядковий номер блоку на сторінці.
  * `createdAt` (`DateTime`), `updatedAt` (`DateTime`).
* **Інваріанти:**
  * `type` обов'язково повинен належати до списку підтримуваних типів `BlockType`.
  * Позиція `position` не може бути від'ємним числом.
* **Доменні методи:**
  * `updateContent(newText)` — оновлення текстового змісту.
  * `changeType(newType)` — конвертація типу блоку (наприклад, перетворення параграфа на заголовок) зі збереженням вмісту.
  * `toggleTodo()` — перемикання прапорця виконання для типу `todo_item`.
  * `setPosition(newPos)` — зміна порядкового номера блоку.

#### 2. `BlockType` (Об'єкт-значення / Value Object)
Словник дозволених типів контентних блоків.
* Значення: `PARAGRAPH`, `HEADING_1`, `HEADING_2`, `HEADING_3`, `TODO_ITEM`, `BULLET_LIST`, `NUMBERED_LIST`, `CODE`, `QUOTE`, `CALLOUT`, `DIVIDER`.

### Контекст 4: Structured Data / Inline Databases

#### 1. `DataTable` (Корінь агрегату / Aggregate Root)
Таблиця обліку зі структурованою схемою.
* **Атрибути:**
  * `id` (`UUID` або `Int`) — унікальний ідентифікатор таблиці.
  * `workspaceId` (`UUID` або `Int`, обов'язкове) — простір прив'язки.
  * `pageId` (`UUID` або `Int`, обов'язкове) — сторінка, всередині якої розташована таблиця.
  * `name` (`String`, обов'язкове) — назва таблиці (наприклад, "Облік робочих серверів").
  * `columns` (`List<Column>`) — набір стовпців схеми.
  * `createdAt` (`DateTime`), `updatedAt` (`DateTime`).
* **Інваріанти:**
  * Таблиця повинна містити щонайменше один стовпець первинної назви (`title` / `text`).
  * Імена стовпців у межах однієї таблиці мають бути унікальними.
* **Доменні методи:**
  * `addColumn(columnName, columnType, options)` — додати новий стовпець до схеми.
  * `removeColumn(columnId)` — видалити стовпець (з відповідним очищенням значень у рядках).
  * `renameColumn(columnId, newName)` — змінити назву стовпця.

#### 2. `Column` (Об'єкт-значення / Value Object)
Специфікація окремого стовпця таблиці.
* **Атрибути:**
  * `id` (`String`) — унікальний ідентифікатор стовпця всередині таблиці (`col_xxx`).
  * `name` (`String`) — заголовок стовпця.
  * `type` (`String`: `text`, `number`, `select`, `date`, `checkbox`).
  * `options` (`Array<String>`, опціонально) — доступні варіанти для типу `select`.

#### 3. `TableRow` (Сутність / Entity)
Запис (рядок) у таблиці даних.
* **Атрибути:**
  * `id` (`UUID` або `Int`) — унікальний ідентифікатор рядка.
  * `tableId` (`UUID` або `Int`, обов'язкове) — посилання на таблицю.
  * `data` (`Map<columnId, Value>`) — значення комірок за ключами колонок.
  * `position` (`Int`) — порядковий номер рядка.
  * `createdAt` (`DateTime`), `updatedAt` (`DateTime`).
* **Інваріанти:**
  * Значення в комірках повинні відповідати типам даних визначених стовпців (наприклад, у колонку `number` не можна зберегти рядок, що не є числом).
* **Доменні методи:**
  * `setCell(columnId, value)` — встановити або оновити значення конкретної комірки.
  * `getCell(columnId)` — отримати значення комірки.

### Контекст 5: Assets & Media Storage

#### 1. `Attachment` (Сутність / Entity)
Завантажений файл або зображення.
* **Атрибути:**
  * `id` (`UUID` або `Int`) — унікальний ідентифікатор файлу.
  * `workspaceId` (`UUID` або `Int`, обов'язкове) — простір власника.
  * `pageId` (`UUID` або `Int`, опціональне) — сторінка, до якої прив'язаний файл.
  * `fileName` (`String`) — оригінальне ім'я файлу.
  * `fileUrl` (`String`) — URL збереженого файлу (локальне сховище або S3).
  * `mimeType` (`String`) — MIME-тип файлу (`image/png`, `application/pdf` тощо).
  * `sizeBytes` (`Int`) — розмір у байтах (обмеження, наприклад, до 10 МБ).
  * `uploadedBy` (`UUID` або `Int`) — автор завантаження.
  * `uploadedAt` (`DateTime`).
* **Інваріанти:**
  * `sizeBytes` не може перевищувати встановлений системний ліміт (10 МБ).
  * `mimeType` повинен бути у списку дозволених типів.

## 3. Матриця зв'язків між сутностями

```
Workspace 1 ─────── N WorkspaceMember N ─────── 1 User
   │
   ├─────── 1 ─────── N Page (Ієрархія: Page 1 ── parent_id ── N Page)
   │                      │
   │                      ├─────── 1 ─────── N Block (1 ── parentBlockId ── N)
   │                      │
   │                      ├─────── 1 ─────── N DataTable 1 ─────── N TableRow
   │                      │
   │                      └─────── 1 ─────── N Attachment
   │
   └─────── 1 ─────── N Attachment
```
